# Summary

General hardening of the GitHub Actions workflows generated by the template, covering security,
reliability, and clarity. No specific incident prompted the change.

# What Changed

## Security

- Workflow expressions (`${{ ... }}`) are no longer interpolated directly into `run:` scripts; values
  are passed through `env:` and referenced as shell variables, which prevents script injection.[^action][^cicd_impl]
- The minisign private key is written to a `mktemp` file under `RUNNER_TEMP` and removed via an
  `EXIT` trap, so it does not persist on self-hosted runners when signing fails.[^action]
- The PyPI token is supplied through `UV_PUBLISH_TOKEN` rather than inline in the command.[^action]

## Reliability

- New `retry.sh` helper retries idempotent network operations (tag push, release publish) up to
  three times with a 15-second delay.[^retry]
- Release creation uploads to an existing release with `--clobber` when present, so a rerun can
  recover from a failure in a later step.[^action]
- A workflow-level `concurrency` group cancels superseded pull request runs, serializes scheduled and
  manual runs per ref, and gives each push a unique group so a pending push run (and its release) is
  never silently cancelled.[^cicd]
- All jobs have `timeout-minutes`.[^cicd_impl]
- The package build step fails when `dist` does not contain exactly one wheel.[^cicd_impl]
- Signing all artifacts now runs in a single Python process instead of one `uv run` per file.[^action]

## Clarity

- The release composite action receives `wheel_filename`, `package_version`, and `coverage_total` as
  explicit inputs instead of relying on job-level environment variables.[^action][^cicd_impl]
- Renames: `python_package_version` → `build_python_version`, `package_coverage` →
  `postprocess_coverage`, `package_name` → `wheel_filename` (the value was always the wheel filename).[^cicd][^cicd_impl]
- Redundant `uv sync --frozen` steps were removed; `uv run` syncs on demand.[^cicd_impl]
- `release_sources.yaml` and `src/AutoGitSemVer.yaml` cross-reference each other so the release
  trigger and version calculation stay in sync.[^release_sources][^autogitsemver]

## Other

- README and DEVELOPMENT docs reference the correct `.minisig` extension and updated placeholders.
- `pyproject.toml` fragment: pytest `addopts` simplified to `-vvv`; ruff ignore comments aligned.
- `tests/All_EndToEndTest.py`: the `.python-version` content assertion is intentionally disabled;
  the value is still normalized for snapshot comparison. Snapshots regenerated.

# Why

The previous workflows interpolated secrets and inputs directly into shell scripts, left the signing
key on disk if a step failed, could lose releases to concurrency cancellation, and had no protection
against transient network failures or hung jobs. Several names (`package_name`,
`python_package_version`, `package_coverage`) did not describe their values.
